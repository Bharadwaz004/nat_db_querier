# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A hybrid Graph + Vector RAG NL-to-SQL assistant. Three services:

- **`frontend/`** — React 18 + Vite chat UI (port 5173)
- **`backend-node/`** — Express API gateway: JWT auth, rate limiting, session/chat-history tracking, proxies to FastAPI (port 3001)
- **`backend_fastapi/`** — Python FastAPI AI engine: the actual NL→SQL pipeline (port 8000)

The Node gateway is a thin proxy — it holds auth/sessions but has no NL-to-SQL logic itself. All pipeline logic lives in `backend_fastapi/src/modules/`.

## Running services

```bash
# One-shot, starts all three (creates sample DB / embeddings cache if missing)
./start.sh

# Individually:
PYTHONPATH=. python -m uvicorn backend_fastapi.src.main:app --port 8000 --reload
cd backend-node && PORT=3001 node src/server.js       # or: npm run dev (uses --watch)
cd frontend && npx vite                                # or: npm run dev
```

Requires `.env` (copy from `.env.example`) with `ANTHROPIC_API_KEY` (or HF creds if `LLM_PROVIDER=huggingface`).

## Architecture: the pipeline (`backend_fastapi/src/modules/orchestrator.py`)

`QueryOrchestrator.process_query()` runs a 7-step pipeline on every `/query` request:

1. **Vector retrieval** (`vector_retrieval.py`) — TF-IDF cosine similarity over cached table/column embeddings picks the top-K relevant tables/columns (`TOP_K_TABLES`, `TOP_K_COLUMNS` env vars).
2. **Graph traversal** (`graph_traversal.py`) — BFS over the FK adjacency graph (`graph/relationships.json`) to find join paths connecting the retrieved tables.
3. **Context building** (`context_builder.py`) — assembles schema + join info into the LLM system prompt.
4. **SQL generation + validation retry loop** (`llm_provider.py`, `sql_validator.py`) — generates SQL, validates against schema via `EXPLAIN` (read-only, blocks non-SELECT/WITH), retries up to `MAX_RETRIES` feeding the validator error back into the prompt.
5. **Execution** (`sql_executor.py`) — runs the query with `PRAGMA query_only = ON`; one extra retry on execution error.
6. **NL response** — LLM turns result rows back into a natural-language answer.

`SchemaIngestion` (`schema_ingestion.py`) is the module that populates everything the rest of the pipeline depends on: it extracts the SQLite schema, generates table/column descriptions, builds the FK graph, and builds/caches the TF-IDF embeddings. It writes to `embeddings/` (pickled vectors + `schema_info.json`) and `graph/relationships.json` so subsequent boots can `load()` from cache instead of re-ingesting.

**Switching databases** (upload, connect-by-path, or reset-to-sample) all funnel through `QueryOrchestrator.reingest()`, which re-runs `SchemaIngestion.ingest()` and rebuilds the retriever/graph/context-builder/validator — these four objects are stateful and tied to whichever DB is currently loaded. `settings.SAMPLE_DB_PATH` is fixed at startup and never mutated, so `/use-sample` can always restore the original demo DB; `settings.DB_PATH` is the mutable "current DB" pointer.

## Security model (don't weaken without asking)

- Node gateway: JWT required on all `/api/*` except `/api/auth/*` and `/api/health`; rate-limited to 100 req/15min.
- FastAPI SQL validator only allows `SELECT`/`WITH`; DML/DDL (DROP, DELETE, INSERT, UPDATE, ALTER, CREATE) rejected before execution.
- SQL execution connection is opened with `PRAGMA query_only = ON` as a second layer of defense.
- JWT secret is shared between Node and FastAPI via `JWT_SECRET` env var — keep in sync if changed.

## Notes

- `backend-node/src/server.js` is a single file (no `routes/`/`middleware/` split yet, despite the empty directories existing under `backend-node/src/`).
- Sessions and users in the Node gateway are in-memory (`Map()`), not persisted — restarting the gateway drops all sessions/logins.
- `data/sample_ecommerce.db` is generated by `data/create_sample_db.py`; `data/uploads/` holds user-uploaded DBs (e.g. the bundled `Chinook.db`).
